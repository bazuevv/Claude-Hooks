# История аккаунта в Accs

Клик по любой строке аккаунта открывает подробности в той же панели. Кнопка
«← Аккаунты» возвращает список. Для смены провайдера служит отдельная кнопка
«Использовать аккаунт». Она открывает предупреждение «Переключение аккаунта»
без изменения настроек. Только кнопка «Переключить аккаунт» выполняет POST смены
аккаунта и после успешного ответа запрашивает перезапуск расширения.
«Отмена», Escape и клик вне предупреждения до подтверждения не отправляют запросов
изменения. При ошибке смены перезапуск не выполняется; при ошибке перезапуска
можно повторить его без повторной смены либо отменить с возвратом прежнего профиля.

В подробностях расположен столбчатый график. При открытии выбран текущий
день с 24 часовыми интервалами. «Месяц» показывает все календарные дни выбранного
месяца; доступны календарь, предыдущий/следующий период и возврат «Сегодня».
Клик по столбцу месяца открывает часы этого дня. Окна лимитов и API выбираются
отдельно. Серые отметки означают отсутствие данных, известный нулевой расход
отмечен зелёным. Над известными значениями показано только число жёлтым цветом.
Подсказка подписочного столбца показывает неделю и её границы по сроку сброса
провайдера; для API остаётся информация о стоимости. Оплаченный период подписки
сохраняется в постоянном журнале и задаёт диапазон верхнего графика.
Если в час/день попадает граница недель, подсказка перечисляет обе недели.
При отсутствии сохранённой даты начала показывается явное отсутствие данных.
Раскрывающаяся таблица удалена; данные отображаются на графиках.

Название аккаунта и статус расположены в одной строке; тариф и почта — ниже.
Кнопка «Использовать аккаунт» синяя. Под реквизитами находятся два независимых
раскрывающихся графика, изначально свёрнутых: сначала жёлтая надпись
«5 часовые лимиты» при наличии этого окна квоты, затем фиолетовая надпись
с пунктирным подчёркиванием «Недельные лимиты». Повторный клик сворачивает график; обновление данных и выбор периода
нижнего графика сохраняют состояние раскрытия.

Недельный график показывает недели текущего оплаченного периода. Выбор остаётся
только при наличии нескольких недельных квот. Пятичасовой показывает отдельный
столбец для каждого сохранённого пятичасового периода, пересекающего текущую
подписку, в хронологическом порядке. При большом количестве столбцов доступна
горизонтальная прокрутка. Подсказка содержит даты начала и конца окна и наблюдавшийся
расход; значения показаны жёлтым над столбцами. Если даты подписки или периоды
неизвестны, показывается отсутствие данных. Пропущенные сбросы не выдумываются.
Оба графика не зависят от выбранного дня или месяца нижнего графика.
Если окно квоты началось внутри отображаемой недели, его известный накопленный расход
в этой неделе учитывается целиком, даже если первые локальные замеры сделаны позже.
Для окна, начавшегося раньше, учитываются только измеренные изменения внутри
недели. Сбросы коротких окон суммируются, данные другого входа исключаются.
Это нижняя оценка зафиксированного расхода: отсутствие замеров не означает ноль.
Недели без данных и будущие недели отмечены серым; номер и границы видны в подсказке.

Даты и часы соответствуют времени ПК. История не ограничена последними 30 днями:
можно открыть любой предыдущий месяц, для которого сохранились журналы.
Повторное открытие сразу показывает кэш выбранного периода, затем обновляет его.
Фонового опроса аккаунтов нет. Поздний ответ не заменяет выбранный пользователем
период. Поле `days` endpoint оставлено для совместимости со старым webview.
Открытие Accs сразу показывает прежний список и запрашивает
`GET /accounts?refresh_usage=1`: для ZAI это принудительный свежий запрос лимитов,
минуя кэш. TTL кэша настраивается в `.claude/patches/claude-custom-config.toml`,
`zaiUsageCacheTtlSec`: `300` — пять минут, `0` — полностью
отключить чтение и обновление файла кэша (текущее значение). При включённом
кэше неудачный запрос сохраняет прежние данные с исходным возрастом.
Промежуточные и итоговые замеры сообщения ZAI передают абсолютные значения
лимитов в Accs через уже выполняемые запросы `/message-times`. Обновляются
полоски открытого списка и снимок для следующего мгновенного открытия.
Данные сопоставляются по файлу аккаунта и времени наблюдения: старый ответ
списка или старое сообщение не заменяют более свежий процент. Дополнительного
фонового опроса провайдера и записи в отключённый кэш нет.
Процент в Accs — общий расход окна, под сообщением — его изменение:
например, начало 6%, конец 8% означает расход сообщения примерно 2%.

Время задачи учитывает остановку обработки в открытом интерфейсе: более
поздний `ui_stop` не заменяется ранним `stop_hook`. Оба времени сохраняются
раздельно (`ui_completed_at`, `server_completed_at`), итоговое `completed_at`
равно более позднему. При закрытом интерфейсе остаётся время Stop-хука.
Замер расхода при этом привязан к выполнению задачи, а не задержке отрисовки.
Таймер считает разность абсолютных времён; блокировка главного потока webview
может задержать обновление цифр, но не вычитается из длительности.
События `message-times` в `.claude/hooks-runtime/http-server.log` содержат ID
сессии/сообщения, источник завершения и задержку интерфейса относительно хука.
Диагностика зависаний — события `perf` в `webview-errors.log`.
В тесте 77152485 от 2026-09-18 Stop-хук записан в 13:47:43 (МСК), а в
13:49:48 журнал получил отчёт о задержке таймера 98,6 с. Точный `ui_stop`
старый код не сохранил; время этого теста задним числом не исправляется.

Замеры стоимости сообщений ZAI всегда запрашивают свежие лимиты при отправке,
промежуточном обновлении и завершении. Интервал промежуточного обновления в
открытом чате задаётся `messageCostsRefreshIntervalSec` в том же конфиге
(сейчас 30 секунд), замеры включаются флагом `messageCostsEnabled`,
как для OpenAI. Под сообщением ZAI отображается только изменение пятичасового
счётчика; недельный продолжает сохраняться для истории аккаунта. При отсутствии
пятичасового замера недельный не подставляется. Абсолютный срок сброса берётся
из ответа провайдера, чтобы задержка сети не создавала ложный сброс окна.

Подписки: используются замеры из журналов стоимости сообщений и из открытий
подробностей. Повторные наблюдения и пересекающиеся задачи объединяются до
вычисления расхода. Значение в процентных пунктах — нижняя оценка изменения
лимита внутри часа/дня между известными замерами. Сбросы, интервалы через границу часа/дня,
смена входа и отсутствие замеров не превращаются в фиктивный нулевой расход.
Изменения лимитов отражают весь аккаунт, включая другие чаты и приложения.

API: суммируется стоимость сообщений с сохранённым аккаунтом в общих журналах
проектов, включая доступные привязанные журналы субагентов. День и час определяются
временем отправки сообщения. Это оценка по токенам и тарифам из
`.claude/message-costs.toml`, а не выписка биллинга. Неизвестный тариф или отсутствие
токенов отмечаются отдельно; неизвестные сообщения не считаются бесплатными.
Старые сообщения без записи аккаунта не приписываются текущему провайдеру.

## Постоянный архив пользователя

Папка определяется через `Path.home() / ".claude" / "usage-history"`:
- Windows: `C:\Users\Vladimir\.claude\usage-history\`;
- Linux: `/home/<пользователь>/.claude/usage-history/` (то есть `~/.claude/usage-history/`).

Она общая для проектов этого пользователя и должна включаться в резервные копии
пользовательских данных. Очистка проекта или `hooks-runtime` её не удаляет.

`quota-periods.sqlite3` — основное постоянное хранилище лимитов, а не временный
индекс. Его необходимо сохранять при резервном копировании. Данные разделены:
- `quota_cycles`: уникальный ID периода, аккаунт, провайдер, тип лимита,
  длительность и границы. Срок сброса хранится здесь один раз;
- `quota_samples`: ссылка `period_id`, процент, время первого и последнего
  наблюдения состояния, признак устаревшего ответа;
- `quota_revisions`: уточнения границы периода, сохраняющие прежний ID;
- `subscriptions`: по одной записи на оплаченный период аккаунта;
- `aliases` и `imports`: соответствия идентификаторов и состояние миграции.

Неизменный процент в том же периоде обновляет `last_seen`, не добавляя строк.
При изменении процента добавляется новое состояние. Падение и возврат процента
сохраняются как отдельные изменения. После сброса создаётся новый ID, даже если
процент совпал. Повторный кэшированный ответ с тем же временем не продлевает
наблюдение. Для графика используются времена начала и конца каждого состояния.
ID наблюдавшейся недели возвращается в `quotaPeriods` и `weeklyUsage` endpoint;
расчётные пустые недели ID не имеют.

`account-usage-samples.jsonl` больше не ведётся. Старый файл импортируется в SQLite
и переносится в `usage-history/legacy/` как неизменная резервная копия. В рабочем
архиве лимитов нет тарифов API, текстов сообщений, ключей, токенов и паролей.

`message-costs-*.jsonl` хранит привязку замеров и тарифов к сообщениям: ID,
начало/прогресс/завершение, путь журнала чата, хеш отправленного текста.
Сам текст сообщения и секреты не сохраняются.

Тарифы в журнале стоимости сообщения нужны для исторической оценки API и
не копируются в архив лимитов. Текущие даты подписки уже находятся в
`~/.claude/.account-subs.json` (для ZAI также поступают от провайдера), но обновляются
при продлении. Таблица `subscriptions` сохраняет прежние оплаченные периоды для
просмотра прошлых месяцев; даты не повторяются в каждом замере расхода.

Аккаунт определяется независимо от имени профиля/проекта. Для подписок используются
ID или почта из метаданных провайдера (в архиве только хеш), для API-профилей —
хеш адреса сервиса и ключа. Когда мост возвращает только `type: apiKey`, определить
учётную запись нельзя: замер не записывается в архив лимитов и не объединяется
с чужой историей. Для этого случая можно задать несекретный `history_id` в
`messageCostAccounts` файла `.claude/patches/claude-custom-config.toml`.

При первом обращении журналы текущего проекта из `hooks-runtime` и прежней
`.claude/usage-history` импортируются в общую базу; журналы сообщений копируются
в общую папку. Повторный перенос не дублирует записи; оригиналы сохраняются как
резервные копии. Новые записи идут в папку
пользователя. Другие проекты мигрируют при обращении через обновлённые хуки.
Старые хеши привязываются к новому аккаунту только при известном соответствии;
неопознаваемые старые записи сохраняются, но не приписываются другому входу.

## Распознавание периодов

Абсолютная граница равна времени наблюдения плюс оставшемуся времени либо
берётся непосредственно из `reset_at`. Для кэшированного ответа учитывается
его возраст. Начало окна — граница минус его длительность, а не дата оплаты.
Обычный отсчёт времени не меняет абсолютную границу и не создаёт новый период.
Допускается погрешность две секунды.

Новая более поздняя граница после окончания прежнего окна подтверждает сброс.
Старый период остаётся с максимальным наблюдавшимся расходом; пятичасовое,
недельное и специальные модельные окна учитываются отдельно. Изменение срока
до прежней границы записывается как корректировка расписания, а не доказанный
сброс. Уменьшение процента само по себе не создаёт новый период.
Без времени сброса сохраняется наблюдение, но границы не выдумываются.

Недельный график использует известные границы провайдера. Пустые прошлые/будущие
недели внутри оплаченного периода могут иметь расчётные границы: это явно
указано в подсказке, такие интервалы не записываются как наблюдавшиеся сбросы.

Журналы сохраняются после перезагрузки. API-оценки также
требуют сохранённых исходных журналов чатов. Историю до начала замеров нельзя
восстановить из одного текущего процента лимита.

Локальный endpoint:
`GET /account-usage-history?file=settings_openai.json&mode=day&date=2026-09-18`
или `mode=month&date=2026-08`. По умолчанию — часы текущего дня.
Он проверяет имя существующего профиля, не переключает его и не возвращает
ключи, тексты сообщений или пути журналов. Ошибки фиксируются штатным `hook_log`.
