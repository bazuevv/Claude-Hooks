# Правила поддержки хуков

**Все изменения в `.claude` всегда адаптировать под Windows, Linux и macOS.**
Это относится к новым хукам, исправлениям, вспомогательным скриптам,
конфигурации и запускаемым ими процессам. Изменение не считается завершённым,
пока не проверена совместимость со всеми тремя ОС.

- Общую логику писать переносимо; системные команды, пути и API выбирать
  явно по ОС. macOS нельзя считать Linux: на ней нет `/proc`, а данные
  VS Code лежат в `~/Library/Application Support`.
- Учитывать Intel и Apple Silicon, пробелы и Unicode в путях, а также
  ограниченный `PATH` приложений, запущенных из графического интерфейса.
- Запускать Python-хуки через `bash .claude/hooks/_run.sh <имя.py>`;
  дочерние Python-процессы — через `sys.executable`. Shell-скрипты сохранять
  с переводами строк LF и поддерживать Bash 3.2, поставляемый с macOS.
- Не полагаться на наличие необязательных утилит. Если функция зависит от
  платформы, добавить реализации для трёх ОС либо явно сообщать об
  отсутствии возможности, сохраняя работу остальных хуков.
- При изменении системной логики добавлять регрессионные проверки для
  Windows, Linux и macOS. Если проверка выполнена с подменой платформы,
  указывать это отдельно от запуска на реальной ОС.

Этот файл подмешивается хуком `project-work-rules.py` в контекст каждой
пользовательской задачи вместе с корневым `CLAUDE.md`, если он существует.

## Требования и запуск

### Общая установка для всех проектов

Регистрации и общие разрешения хранятся в `settings-hooks.json`. Claude Code
сам этот файл не читает: установщик и переключатель аккаунтов объединяют его
с активным `~/.claude/settings.json`. Общие ключи идут первыми, списки хуков
и разрешений объединяются без повторов, параметры провайдера сохраняются.
Порядок ключей в JSON не определяет порядок выполнения хуков.

После проверки зависимостей установите комплект для текущего пользователя:

```bash
bash .claude/hooks/_run.sh deploy_hooks.py --source .claude --global
```

Команда работает в macOS, Linux и Windows с Git Bash. На Windows можно также
вызвать `deploy_hooks.py` через установленный Python 3.11+ из PowerShell.
Скрипты и ресурсы устанавливаются в `~/.claude/hooks` и `~/.claude/patches`,
регистрации — в `~/.claude/settings-hooks.json`. Существующие аккаунты и сессии
сохраняются. Заменяемые файлы копируются в `~/.claude/backups/global-hooks-*`;
при ошибке установки уже заменённые файлы восстанавливаются.

Переключение провайдера, возврат на Anthropic, сохранение настроек аккаунта
и создание активного `settings.json` каждый раз читают общий файл заново.
Повреждённый JSON останавливает операцию до замены активных настроек.
`settings-hooks.json` не показывается в списке аккаунтов. Новый профиль OpenAI
также получает общий слой при создании. Внешние программы, которые сами
перезаписывают `settings.json`, этим механизмом не управляются.

Сервер хуков при запуске и каждые 30 секунд проверяет OpenAI: если
`settings_openai.json` отсутствует, создаёт его по авторизованному аккаунту
Codex и доступным моделям; если мост остановлен — запускает его. Проверка
также вызывается при открытии Accs, с ограничением повторов до одного раза
в 30 секунд. Без входа в Codex профиль не создаётся; после входа проверка
повторяется автоматически. Существующий профиль не перезаписывается,
активный аккаунт не переключается. Если удалён профиль активного OpenAI,
его параметры восстанавливаются из действующего `settings.json`.

В общей установке редактируйте конфигурацию в `~/.claude/patches/` и
`~/.claude/message-costs.toml`. Состояние хранится в `~/.claude/hooks-runtime/`,
маркеры ByPass разделены по идентификатору сессии. Правила работы с проектом
и проверка путей используют текущий проект. Общие настройки интерфейса
читаются из пользовательских настроек VS Code; настройки первого открытого
проекта не распространяются на остальные. Перезапуск после смены аккаунта
адресуется проекту выбранной сессии; остальные открытые окна нужно
перезапустить отдельно, чтобы их процессы подхватили нового провайдера.

При переходе с проектной установки уберите регистрации этого комплекта из
проектного `.claude/settings.json`, сохранив остальные настройки. Иначе две
копии скриптов могут запускаться одновременно. После установки перезапустите
VS Code. Исходный `settings-hooks-template.json` хранит регистрации и служит
защищённым шаблоном установки. При сборке он становится `settings-hooks.json`;
разрешения из проектного файла сохраняются, а пути преобразуются автоматически.

### Графический установщик macOS

**macOS — графический установщик:** откройте `MacOS_Install.app` двойным щелчком
в Finder. Основное окно имеет размер 760 × 500; проверка, установка, обновление
и результаты остаются в одном представлении. Выбор удаляемых компонентов
временно заменяет его внутри того же окна. Длинные списки
прокручиваются. Отдельными остаются системные диалоги выбора файла и прав
администратора. Приложение содержит собственную копию хуков, поэтому его можно
переносить отдельно от исходного проекта.

1. Выберите язык интерфейса: **Русский** или **English**. По умолчанию
   учитывается язык macOS; ручной выбор сохраняется. Переключение работает
   без перезапуска, в том числе во время проверки.
2. Нажмите «Проверить компоненты». Этот шаг ничего не устанавливает.
   Результаты показаны списком компонентов со значками и статусами.
   Встроенные Bash и звуковой проигрыватель не входят в список зависимостей
   macOS. В списке пять компонентов, и счётчик готовности учитывает эти строки.
   Если всё готово, приложение сообщит, что новые пакеты не нужны.
   Если есть недостающие компоненты, основная правая кнопка сменится на
   «Установить компоненты». Загрузка начнётся только после нажатия.
3. Когда зависимости готовы, установщик сразу проверяет наличие этого комплекта
   в `~/.claude`. Если хуков нет, нажмите «Установить хуки». Если они уже есть,
   интерфейс показывает установленную и доступную версии, а кнопка называется
   «Обновить хуки». У прежних установок без маркера честно указывается, что номер
   версии не записан. Обновление запускается без отдельного экрана подтверждения.
   Установка выполняется в **`~/.claude` текущего пользователя**, без выбора
   папки проекта. При обновлении заменяемые файлы сохраняются в
   `~/.claude/backups/global-hooks-*`; аккаунты, сессии и прочие настройки сохраняются.
4. После нажатия «Установить хуки» или «Обновить хуки» список компонентов и
   сообщение под ним сворачиваются. На их месте показывается ход операции, а
   затем только версия установленного комплекта и путь `~/.claude`. Если VS Code
   открыт, основная правая кнопка меняется на «Перезапустить VS Code».
   Обычное завершение позволяет редактору запросить сохранение файлов;
   принудительное завершение не используется. Если редактор закрыт, кнопка
   называется «Открыть VS Code». Хуки доступны во всех проектах — копировать `.claude`
   в каждый проект больше не нужно. При переходе с проектной установки удалите
   только регистрации этого комплекта из проектного `.claude/settings.json`,
   чтобы не запускать хуки дважды. Установщик не ищет и не изменяет ваши проекты.

На первом экране всегда только три кнопки: слева **«Удалить зависимости»**,
справа **«Отменить»** и крайняя правая основная кнопка. Основная кнопка последовательно
меняется: **«Проверить компоненты» → «Установить компоненты» → «Установить хуки» / «Обновить хуки»
→ «Открыть VS Code» / «Перезапустить VS Code»**.
Кнопка «Отменить» закрывает установщик, если сейчас не выполняется операция.
Кнопка **«Удалить зависимости»** сначала показывает список с флажками:
устанавливаемые компоненты и дополнительный компонент `uv / uvx`. Bash и звук появляются здесь только
при обнаружении дополнительно установленных версий. Можно выбрать зависимости
по отдельности или нажать «Выбрать все», чтобы отметить все доступные для удаления.
По умолчанию ничего не выбрано. Отсутствующие и требующие ручного
удаления компоненты недоступны для выбора. Встроенные средства macOS скрыты. Под списком показаны точные
пути для текущего выбора. После «Удалить выбранное» и закрытия VS Code удаляются
только выбранные компоненты:

- Расширения Claude Code и Codex через VS Code CLI, затем сам VS Code из
  `~/Applications` и `/Applications`.
- Node.js из `~/Library/Application Support/ClaudeHooks/tools/node`.
- Установленные через uv версии Python 3.13 из `~/.local/share/uv/python`,
  ведущие к ним ссылки в `~/.local/bin`, а также `uv` и `uvx` из этой папки.
- Обнаруженные Homebrew-пакеты Bash, Node.js, Python, FFmpeg и uv, а также cask
  VS Code — через Homebrew. Защита зависимостей других пакетов не отключается.
- Xcode Command Line Tools, если существует `/Library/Developer/CommandLineTools`.
  Этот отдельный пункт удаляется без Корзины после системного запроса прав
  администратора; само приложение Xcode и его данные не удаляются. Удаление
  может повлиять на Git, Homebrew и сборку других программ. Для работы готового
  установщика этот комплект не требуется.

Файлы обычных установок перемещаются в Корзину. Расширения и пакеты Homebrew
удаляются штатными командами. **В список могут попасть программы, установленные
вручную до запуска установщика**; их удаление влияет и на другие проекты.
Системные Bash/Python/afplay, само приложение Xcode, сам Homebrew, проекты,
`~/.claude`, аккаунты, настройки редактора и кэши сохраняются. Отдельный Codex CLI
сохраняется: для этого комплекта требуется расширение, включающее свой CLI.
Другие версии Python uv, Python.org, MacPorts и обнаруженные нестандартные
установки показываются как требующие ручного удаления. При ошибке операция
останавливается и не выдаёт частичное удаление за полное; доступна диагностика.
Bash и звуковые уведомления можно выбрать для удаления, если найдены
дополнительные Homebrew-пакеты `bash`, `ffmpeg` или `ffmpeg@…`. Удаление этих
пакетов сохраняет встроенные `/bin/bash` и `/usr/bin/afplay`; они уже есть
в чистой macOS и не устанавливаются этим комплектом. Нестандартные копии
из MacPorts или пользовательских каталогов показываются для ручного удаления.
Python и uv выбираются независимо; снятый флажок сохраняет компонент.
При удалении только VS Code невыбранные расширения остаются на диске. Homebrew
может отклонить удаление программы, необходимой другим установленным пакетам.
Удаление работает без Python и не скачивает ПО для собственного запуска.
Эта кнопка относится к macOS-приложению; на Windows/Linux удаление программ
выполняется средствами ОС или пакетного менеджера.

Окно «Для команды python3 требуются инструменты командной строки» и лицензия
Xcode относятся к **macOS Command Line Tools**, а не к интерфейсу установщика.
На чистой macOS вызов `/usr/bin/python3` может запускать этот системный диалог.
Диспетчер и установщик теперь пропускают этот загрузчик, в том числе ссылки на
него. Готовому `.app` Command Line Tools не нужны: при необходимости используется
проверенная готовая сборка Python без `uv` и `install_name_tool`. Для сборки
самого `.app` инструменты разработчика нужны.

### Начальный профиль API

В эту локальную сборку включён явно предоставленный `settings_API.json`.
Другие аккаунты с компьютера сборки автоматически не собираются. Файл копируется
в пользовательскую `~/.claude`, если такого профиля ещё нет. Существующий API-профиль,
в том числе с другим регистром имени файла, не перезаписывается.

Если пользователь ещё не настроил активное подключение, профиль API становится
активным сразу, даже когда рядом уже сохранён неактивный профиль OpenAI или
другого провайдера. Его параметры объединяются с общими хуками в `settings.json`,
исходные настройки сохраняются в `settings.json.bak`, а `.active-account`
указывает на профиль API. Действующие ключи/адрес провайдера, OAuth-файл или
валидный маркер аккаунта сохраняют текущий выбор. Старый `settings.json.bak` и
маркер несуществующего профиля больше не оставляют активный файл без подключения.
При сбое записи профиль и настройки откатываются вместе с установкой хуков.
Правило общее для macOS, Windows и Linux.

**Этот установщик содержит API-ключ из профиля. Передача `.app` передаёт и ключ.**
Локальный файл профиля и его копия в `.app` исключены из Git; ключи не выводятся
в журнал установки. Сам профиль хранится с правами `0600` на macOS/Linux.

При переносе на другой компьютер снова проверьте зависимости установщиком.
Истории сессий, журналы, `settings.local.json` и старые пути к программам
не включаются в распространяемый пакет. Выбранные пользователем параметры
`claude-custom-config.toml` и `message-costs.toml` сохраняются при обновлении.
Терминал и консольный вывод скрыты. Ход работы показан графически:
индикаторами проверки, значками готовности и общим прогрессом. При ошибке
появляется локализованное сообщение и кнопка сохранения диагностики в файл.
Неудачная установка не отмечается как успешная.

Приложение собрано для Intel и Apple Silicon, macOS 12+. Устанавливаемые
версии сторонних программ могут требовать более новую macOS.
Исходники графического интерфейса находятся в `macos-installer/` исходного
проекта; переводы — в `macos-installer/locales/ru.json` и `en.json`.
После изменения хуков или интерфейса пересоберите встроенный пакет на Mac:

```bash
python3 -B .claude/macos-installer/build.py
```

Для сборки нужны Xcode Command Line Tools; для запуска готового `.app` они
не нужны. Сборка имеет локальную ad-hoc подпись, без Developer ID и нотарификации
Apple. Windows и Linux используют установщики ниже.

Из корня проекта запустите установщик. Он проверяет версии и работоспособность
зависимостей, устанавливает отсутствующие или неподходящие и повторяет проверку.
Повторный запуск пропускает уже работающие зависимости. Флаг `--global` /
`-Global` после проверки устанавливает хуки в общую `~/.claude`; запуск без
этого флага устанавливает только зависимости.

**macOS / Linux / Windows с Git Bash:**

```bash
bash .claude/install.sh --global
```

**Windows без Git Bash — из PowerShell:**

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .claude/install.ps1 -Global
```

Только проверка, без скачивания, установки и записи путей:

```bash
bash .claude/install.sh --check
```

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .claude/install.ps1 -Check
```

Если подходящего Python ещё нет, консольный режим `--check` сообщает об этом
и завершается. Графическое приложение macOS проверяет каждый компонент
напрямую средствами Swift и системных утилит: отсутствие Python не мешает
сразу определить состояние Node.js, VS Code и сохранённых расширений.
VS Code проверяется без Python и других дополнительных зависимостей. Приложение
проверяет идентификатор, формат версии, основной исполняемый файл и `product.json`
найденного `.app`, не запуская Electron или CLI VS Code. Оставшийся каталог,
сломанный bundle или устаревшая запись Launch Services не дают статус «Готово».
Расширения проверяются напрямую по их манифестам в каталогах VS Code. Python и
Node.js проверяются прямым запуском найденных
бинарников, рабочий бинарник Codex — отдельно. Эти проверки не зависят друг от
друга.
Сам установщик и все фоновые команды работают из системного временного каталога.
Проверка компонентов не копирует и не распаковывает payload: это происходит
только после явного запуска установки. Поэтому расположение приложения или
проекта внутри `Documents` не требует доступа к пользовательской папке во время
проверки.
Для отсутствующих компонентов графическое приложение запрашивает у официальных
серверов актуальный размер архива или VSIX для архитектуры этого Mac и показывает
его в скобках после названия. На этапе определения размера файлы пакетов не
скачиваются; если сервер не вернул `Content-Length`, компонент остаётся без числа.
Системный загрузчик `/usr/bin/python3` в macOS не запускается, поэтому проверка
не вызывает предложение установить Command Line Tools. Встроенные `/bin/bash`
и `/usr/bin/afplay` считаются частью поддерживаемой macOS и вообще не включаются
в проверку или список зависимостей графического установщика.
Код возврата `0` означает, что проверки пройдены; `1` — недостающую зависимость
или ошибку. Ошибка установки не выдаётся за успешный результат.

| Зависимость | Проверка и установка |
| --- | --- |
| Python 3.11+ | Проверка `tomllib`, SSL, SQLite, ctypes и других используемых модулей стандартной библиотеки. При необходимости устанавливается Python 3.13: через uv на macOS/Linux, через WinGet на Windows. Системный Python macOS/Linux не заменяется. |
| Bash | На Windows устанавливается Git for Windows; WSL Bash не заменяет Git Bash. В macOS/Linux установщик запускается имеющимся Bash. |
| Node.js 18+ | Проверка запуска и версии; на macOS устанавливается официальный Node.js 22 для нужной архитектуры с проверкой SHA-256, на Windows — LTS. Используется для проверки JS-патчей. |
| Звуковой проигрыватель | На macOS используется встроенный `afplay`; на Windows/Linux устанавливается и проверяется FFmpeg / `ffplay`. |
| WirePlumber / wpctl | Только Linux: для управления громкостью звуковой сцены. Работа этой функции также требует действующего PipeWire-сеанса. |
| VS Code и Claude Code | Проверка VS Code CLI и расширения `anthropic.claude-code`, установка при отсутствии. |
| Расширение Codex | Проверка наличия `openai.chatgpt` в VS Code; при отсутствии расширение устанавливается, даже если отдельный Codex CLI уже работает. Дополнительно проверяется запуск CLI, необходимого хукам. |
| Windows PowerShell / .NET | Проверка системных библиотек Windows для экспорта изображений. При повреждении компонентов ОС сообщается ошибка. |

Сторонних Python-пакетов у текущих хуков нет: `pip install` не требуется.
Установщик не выполняет вход в аккаунты и не применяет патчи к расширениям.

На macOS Python устанавливается через uv, Node.js — в
`~/Library/Application Support/ClaudeHooks/tools`, VS Code при отсутствии —
в `~/Applications`. Если существующий VS Code не проходит проверку, установщик
не заменяет его и не создаёт вторую копию, а предлагает исправить или обновить
редактор. Для обычной установки на Mac не нужны Homebrew, терминал
или пароль администратора. На Windows программы устанавливаются через WinGet. Поддерживаются
Windows 10 1809+ / Windows 11 и Linux с `apt-get`, `dnf`, `pacman` или `zypper`.
В Linux репозитории должны содержать подходящие версии пакетов; если они
устарели или недоступны, установщик завершится с объяснением ошибки.
Автоустановка самого VS Code в Linux поддерживает DEB/RPM на x64/arm64;
на Arch необходимо заранее установить официальный VS Code. Нужны интернет
и, для системных пакетов, права администратора: возможен запрос пароля/UAC.

Найденные пути записываются в `.claude/install-state/` (исключён из Git).
Диспетчер `_run.sh` использует их для Python и `PATH` дочерних процессов,
поэтому после установки не требуется вручную добавлять программы в `PATH`
VS Code. После переноса проекта на другой компьютер запустите установщик заново.

Нужны Bash (на Windows — Git Bash) и **Python 3.11+** со стандартным модулем
`tomllib`. Системный Python 3.9 в macOS не подходит. После установки зависимостей
перезапустите VS Code. Диспетчер проверяет версию, ищет Python в `PATH`,
а на macOS также в стандартных каталогах Homebrew, MacPorts и python.org.
Для нестандартной установки задайте переменную окружения
`CLAUDE_HOOK_PYTHON` с полным путём к интерпретатору в окружении VS Code.

Настройки и кэш VS Code ищутся в `%APPDATA%` на Windows,
`$XDG_CONFIG_HOME` (или `~/.config`) на Linux и
`~/Library/Application Support` на macOS. Поддерживаются Code и Code Insiders.

Проверка из корня проекта:

```bash
bash .claude/hooks/_run.sh test_host_platform.py
bash .claude/hooks/_run.sh test_install_dependencies.py
bash .claude/hooks/_run.sh test_deploy_hooks.py
bash .claude/hooks/_run.sh test_audio_player.py
```

После применения патчей расширения выполните `Developer: Reload Window`.
Необязательные возможности имеют отдельные зависимости: звук использует
`afplay` на macOS и `ffplay` на Windows/Linux (управление звуковой сценой —
`wpctl` на Linux), нативный экспорт
изображений в текущей реализации доступен только на Windows.

Источники команд установки: [uv](https://docs.astral.sh/uv/guides/install-python/),
[Homebrew](https://brew.sh/),
[WinGet](https://learn.microsoft.com/en-us/windows/package-manager/winget/),
[VS Code CLI](https://code.visualstudio.com/docs/configure/command-line).

### Сервер и открытые окна VS Code

В конце общей установки применяются патчи расширения и запускается сервер.
`hook_supervisor.py` вызывается из extension host при активации, изменении списка
папок и каждые 30 секунд. Для запуска сервера не нужна открытая папка или первая
отправка сообщения. Каждый extension host передаёт своей панели отдельный
идентификатор; перезапуск направляется в это окно даже до появления истории
сессии. Для пустого окна используется штатная перезагрузка окна VS Code.

В открытых проектах проверяются `settings.json`, `settings.local.json` и
`settings-hooks.json` внутри `.claude`. Удаляются только точные регистрации
этого комплекта, уже включённые глобально, с тем же событием и параметрами.
Остальные хуки, разрешения и параметры аккаунтов сохраняются. Исходный файл
копируется в `<проект>/.claude/backups/global-migration-*`. Символические ссылки
и файлы с неразбираемым JSON не перезаписываются. Сами папки с локальными
скриптами не удаляются. Для уже запущенных сессий примените изменения перезапуском
VS Code после обновления установщика.

### Загрузка компонентов в macOS

Python устанавливается из закреплённой сборки `python-build-standalone` для Intel
или Apple Silicon с проверкой SHA256. Адреса и контрольные суммы находятся в
`hooks/install_python_macos.sh` и взяты из каталога загрузок Astral uv. При
обновлении версии обновляйте оба адреса и обе суммы. Готовый интерпретатор не
требует запуска `uv python install` или `install_name_tool`, поэтому установка
Command Line Tools для этого шага не нужна. Каталог интерпретатора:
`~/Library/Application Support/ClaudeHooks/tools/python`; он включён в удаление
компонента Python. Linux и Windows сохраняют свои установочные механизмы.

В интерфейсе показываются реальные проценты скачанных байтов, затем этапы
проверки, распаковки и установки. Если сервер не передаёт размер файла,
показывается этап загрузки без выдуманного процента; по окончании — 100%.
После установки недостающих компонентов приложение повторяет автономную проверку
всего списка. VS Code и расширения снова проверяются без запуска редактора;
затем устанавливаются только оставшиеся компоненты.
Расширения для macOS скачиваются из Marketplace в виде VSIX нужной архитектуры
и устанавливаются штатной командой VS Code. После успешного открытия или
перезапуска редактора установщик закрывается; при ошибке остаётся открытым.
Перед открытием VS Code установщик проверяет `xcode-select -p`, не запуская
системный `git`. Если Command Line Tools отсутствуют, только для запуска из
установщика передаётся `--disable-extension vscode.git`: это предотвращает
системное окно установки инструментов разработчика и не отключает Claude Code
или Codex. При наличии Command Line Tools редактор запускается без этого флага.
